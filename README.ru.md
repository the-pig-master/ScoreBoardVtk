# ScoreBoardVtk

`ScoreBoardVtk` это современное приложение на `C# / .NET 8` для управления legacy-спортивным табло.

Проект рассчитан на работу с реальным физическим табло через последовательный порт и включает:

- `WPF`-приложение оператора,
- `CMD`-утилиту для диагностики `COM`-портов и проверки сигнала,
- общий слой `Core` с матчевой логикой, протоколом, настройками и runtime,
- unit-тесты для критичной логики.

Английская документация: [README.md](C:/WORK/Repositories/ScoreBoardVtk/README.md)

## Структура solution

- `ScoreBoardVtk.Core`
  - модели, логика controller, протокол, транспорты, настройки, runtime
- `ScoreBoardVtk.Wpf`
  - настольный интерфейс оператора
- `ScoreBoardVtk.Cmd`
  - консольная утилита диагностики
- `ScoreBoardVtk.Tests`
  - unit-тесты

Открывать solution:

- `C:\WORK\Repositories\ScoreBoardVtk\ScoreBoardVtk.sln`

## Основной функционал

### Баскетбол

- управление счетом хозяев и гостей
- счетчики фолов
- управление четвертями и овертаймом
- основной игровой таймер
- настраиваемый пресет основного времени
- настраиваемый пресет овертайма
- таймер броска `24 / 14`
- кнопки `Set 24`, `Set 14`, `Run 24`, `Run 14`
- сброс только таймеров
- ручная установка счета, фолов, периода, времени и `24` через отдельное окно
- предупреждение при смене периода, если время еще не истекло

### Волейбол

- управление счетом хозяев и гостей
- переход по сетам
- счетчики сетов

### Инструменты оператора

- ручной звуковой сигнал
- бегущая строка
- настраиваемые горячие клавиши
- локализация интерфейса на английский и русский
- опциональная вкладка `Debug` для ручной отправки payload

### Технические возможности

- формирование legacy-пакетов `AT+GD`
- `CRC16`
- поддержка `CP1251` для старого протокола
- профили запуска `Hardware`, `Mock`, `Development`
- встроенный `MOCK` transport
- elapsed-time логика баскетбольных таймеров

## Файлы конфигурации

Приложение использует два JSON-файла.

### `hostsettings.json`

Расположение для WPF:

- [hostsettings.json](C:/WORK/Repositories/ScoreBoardVtk/ScoreBoardVtk.Wpf/hostsettings.json)

Назначение:

- выбор профиля запуска
- настройка timing/publish интервалов runtime
- указание файла игровых настроек
- управление видимостью вкладки `Debug`

Профили:

- `Hardware`
  - доступны только реальные последовательные порты
- `Mock`
  - доступен только встроенный порт `MOCK`
- `Development`
  - доступны реальные порты и `MOCK`

Полезные поля:

- `showDebugTab`
  - `true` = показывать вкладку `Debug`
  - `false` = скрывать вкладку `Debug`

Release-настройки:

- [hostsettings.Release.json](C:/WORK/Repositories/ScoreBoardVtk/ScoreBoardVtk.Wpf/hostsettings.Release.json)
  - `profile = Hardware`
  - `showDebugTab = false`

### `settings.json`

Расположение для WPF:

- [settings.json](C:/WORK/Repositories/ScoreBoardVtk/ScoreBoardVtk.Wpf/settings.json)

Назначение:

- выбранный `COM`-порт
- язык интерфейса
- игровой режим
- пресеты времени
- длительности сигналов
- горячие клавиши
- настройки бегущей строки
- режим отображения фолов
- настройки legacy-payload

Важные поля:

- `mainSignalDurationSeconds`
  - длительность основного сигнала окончания периода
- `shotClockSignalDurationTenths`
  - длительность сигнала `24` секунд
- `useMainSignalFieldForShotClockSignal`
  - `true` = передавать сигнал `24` через тот же payload-флаг, что и основной сигнал
  - `false` = использовать отдельный payload-флаг для сигнала `24`

Важное поведение:

- настройки на вкладке `Settings` работают в staged-режиме
- изменения применяются только после нажатия `Apply`

## Работа с WPF-приложением

### Базовый порядок работы

1. Открой вкладку `Settings`.
2. Выбери нужный `COM`-порт.
3. Установи игровой режим и пресеты времени.
4. Нажми `Apply`.
5. Открой порт.
6. Перейди на вкладку `Game` и управляй табло.

### Управление баскетболом

Основные кнопки:

- `Start / Stop`
  - запускает или останавливает основной игровой таймер
- `Signal`
  - ручной звуковой сигнал, пока кнопка удерживается
- `Period / Set`
  - меняет четверть
- `Reset`
  - сбрасывает только таймеры
- `Set`
  - открывает окно ручной установки значений табло

Управление `24` секундами:

- `Start / Stop`
  - запускает или останавливает текущее значение таймера броска
- `Run 24`
  - устанавливает `24` и сразу запускает таймер
- `Run 14`
  - устанавливает `14` и сразу запускает таймер
- `Set 24`
  - устанавливает `24` без запуска
- `Set 14`
  - устанавливает `14` без запуска

### Окно `Set`

Окно `Set` позволяет вручную задать:

- счет хозяев
- счет гостей
- фолы / сеты хозяев
- фолы / сеты гостей
- номер периода
- основное игровое время
- время таймера `24`

Кнопка `Reset All` сбрасывает только значения внутри этого окна.
Изменения применяются только после нажатия `OK`.

### Бегущая строка

В нижней части вкладки `Game` можно:

- включить или выключить бегущую строку
- отредактировать текст, который отправляется на табло

### Вкладка `Debug`

Вкладка `Debug` опциональна и управляется через `hostsettings.json`.

На ней есть:

- `Debug mode`
  - останавливает периодическую автоматическую отправку payload
- текстовое поле payload
- `Send`
  - отправляет введенный payload на табло

Если `Debug mode` выключить, периодическая автоматическая отправка возобновляется.

## Горячие клавиши

Горячие клавиши настраиваются на вкладке `Settings`.

Поддерживаемые действия:

- старт / стоп игрового таймера
- старт / стоп таймера `24`
- `Set 24`
- `Set 14`
- `Run 24`
- `Run 14`
- счет хозяев `+1 / -1`
- счет гостей `+1 / -1`
- фолы хозяев `+1 / -1`
- фолы гостей `+1 / -1`

Особенности:

- горячие клавиши работают на вкладке `Game`
- они не срабатывают, когда курсор стоит в текстовом поле или `ComboBox`
- назначенная клавиша показывается в скобках на соответствующей кнопке

## CMD-утилита

Консольный проект предназначен для диагностики и быстрой проверки оборудования.

Команды:

- `list`
  - выводит список всех доступных `COM`-портов
- `buzz <COMx>`
  - отправляет звуковой сигнал длительностью `0.3` секунды на указанный порт
- `scan-all`
  - по очереди отправляет тестовый сигнал на все `COM`-порты с паузой `1` секунда
- `watch`
  - отслеживает подключение и отключение портов

Примеры:

```powershell
dotnet run --project C:\WORK\Repositories\ScoreBoardVtk\ScoreBoardVtk.Cmd\ScoreBoardVtk.Cmd.csproj -- list
dotnet run --project C:\WORK\Repositories\ScoreBoardVtk\ScoreBoardVtk.Cmd\ScoreBoardVtk.Cmd.csproj -- buzz COM3
dotnet run --project C:\WORK\Repositories\ScoreBoardVtk\ScoreBoardVtk.Cmd\ScoreBoardVtk.Cmd.csproj -- buzz MOCK
dotnet run --project C:\WORK\Repositories\ScoreBoardVtk\ScoreBoardVtk.Cmd\ScoreBoardVtk.Cmd.csproj -- scan-all
dotnet run --project C:\WORK\Repositories\ScoreBoardVtk\ScoreBoardVtk.Cmd\ScoreBoardVtk.Cmd.csproj -- watch
```

Интерактивный режим:

- запусти CMD-приложение без аргументов
- используй клавиатурное меню со стрелками и `Enter`

## Сборка, тесты и упаковка

Сборка:

```powershell
dotnet build C:\WORK\Repositories\ScoreBoardVtk\ScoreBoardVtk.sln
```

Запуск тестов:

```powershell
dotnet test C:\WORK\Repositories\ScoreBoardVtk\ScoreBoardVtk.Tests\ScoreBoardVtk.Tests.csproj
```

Создание `Release`-архивов и инсталляторов:

```powershell
powershell -ExecutionPolicy Bypass -File C:\WORK\Repositories\ScoreBoardVtk\build\package.ps1
```

Что получается на выходе:

- `.zip`-пакеты для `win-x86` и `win-x64`
- `setup.exe`-инсталляторы для `win-x86` и `win-x64`

Требование для инсталляторов:

- должен быть установлен `Inno Setup 6`, чтобы был доступен `ISCC.exe`

Особенности packaging:

- publish идет в `Release`
- publish идет как `self-contained`
- в пакет попадают и `WPF`, и `CMD`
- `CMD` размещается в `tools\cmd`

## Примечания по железу

Проект сохраняет старую модель обмена с табло и формат пакетов, но финальную проверку все равно нужно делать на реальном контроллере табло.

Важно:

- оригинальная старая система использовала низкоуровневую работу с последовательным портом / `RS-485`
- текущий проект воспроизводит игровую логику и генерацию payload
- совместимость с реальным устройством нужно проверять на целевом оборудовании
